# SEO, GEO и AI: InterDIZ

Основной адрес: **https://interdiz.ru/**. География услуг: **вся Россия**. Эти значения подтверждены владельцем 6 ноября 2026 года. Настройки находятся в `seo.config.mjs`.

## Что подготовлено

| Страница | Назначение | Schema.org |
| --- | --- | --- |
| `/` | Студия и семь направлений работы | Organization, WebSite, WebPage, OfferCatalog, Service, FAQPage, ItemList, CreativeWork |
| `/portfolio.html` | Девять проектов | CollectionPage, BreadcrumbList, ItemList, CreativeWork |
| `/web-development.html` | Разработка сайтов и четыре формата | WebPage, BreadcrumbList, Service, OfferCatalog, FAQPage, ItemList, CreativeWork |

На каждой странице есть уникальные title и description, абсолютный canonical, Open Graph, Twitter Card, русская локаль и разрешение расширенных сниппетов. Заголовок вкладки не зависит от темы. Фавиконы вынесены из data URL в доступные роботу SVG-файлы с прежними рисунком и цветами. Предзагрузка существующих локальных шрифтов сокращает задержку их обнаружения.

JSON-LD вставляется в исходный HTML до публикации. Для его чтения не нужны JavaScript, внешние библиотеки или запросы к API. Контакты берутся из футера главной, вопросы и ответы — из соответствующих FAQ, услуги и проекты — из существующих карточек. Видимые тексты, CSS, компоновка и анимации не изменены. FAQ включает только вопросы и ответы; этапы работы не выдаются за FAQ или инструкции HowTo. Отзывы не размечаются как собственный рейтинг студии. Не добавлены неподтверждённые цены, адреса, юридические сведения, награды или даты обновления.

`dist/sitemap.xml` содержит только три канонических адреса и изображения проектов. Темы, фильтры и якоря не создают отдельные страницы в карте. Даты lastmod намеренно не проставлены: время запуска генератора не означает содержательного обновления страницы.

`dist/robots.txt` разрешает обход страниц, изображений, CSS и JS, включая поисковых ИИ-роботов. Для Яндекса Clean-param объединяет варианты темы и старого параметра topic. Фильтр category меняет выборку, поэтому в Clean-param не включён; его страницы указывают canonical полного портфолио. Варианты URL не закрыты от обхода, чтобы робот мог увидеть canonical.

`dist/llms.txt` — дополнительная навигация по существующим материалам и контактам. Это необязательный экспериментальный формат, а не требование Яндекса или Google и не гарантия цитирования. Основой GEO остаются доступный HTML, корректная индексация и подтверждённое содержание.

## Обновление и проверка

```sh
npm run prepare:site
npm run check
```

Без npm, если в среде доступен только Node.js:

```sh
node scripts/sync-footer.mjs
node scripts/sync-seo.mjs
node scripts/sync-seo.mjs --check
node --test scripts/seo.test.mjs
```

`server.mjs` при старте синхронизирует футер и SEO. GitHub Pages выполняет подготовку и проверки перед публикацией. Генератор обновляет только блок между `SEO:START` и `SEO:END`, а также robots, sitemap и llms. Вручную этот блок редактировать не нужно. Изменения видимых текстов выполняются в обычном HTML; затем запускается `prepare:site`.

Для новой страницы в корне `dist` добавить запись в `seo.config.mjs` с её уникальными метаданными и соответствующим типом содержимого; при новом типе страницы расширить генератор. Проверка сообщает о незарегистрированных HTML-страницах, устаревшей разметке, отсутствующих файлах, ошибочных ссылках и нарушенных связях Schema.org.

## При запуске на основном домене

1. Разместить содержимое `dist` в корне `https://interdiz.ru/`, включая robots, sitemap, llms и оба favicon. Файл `AGENTS.md` — инструкция для разработки; его не требуется размещать на публичном сервере.
2. На выбранном хостинге настроить постоянные редиректы HTTP → HTTPS, www → interdiz.ru и `/index.html` → `/`, сохраняя query-параметры. Локальный Node-сервер уже возвращает 301 для `/index.html`; его настройки не переносятся автоматически на статический хостинг.
3. Проверить реальные ответы: существующие страницы — 200, неизвестный адрес — 404, sitemap — XML, robots и llms — text/plain. Отсутствующие страницы не должны возвращать главную со статусом 200. Убедиться, что CDN, WAF и защита от ботов не блокируют разрешённых роботов и что отсутствует HTTP-заголовок X-Robots-Tag: noindex.
4. Закрыть публичные тестовые домены от индексации средствами их хостинга либо доступом по паролю. Production-файлы robots и canonical предназначены для основного домена. Canonical — сигнал выбора адреса, он не заменяет ограничение доступа к тестовой копии.
5. Подтвердить основной домен в Яндекс Вебмастере и Google Search Console и отправить `https://interdiz.ru/sitemap.xml`. Коды подтверждения зависят от аккаунта владельца; фиктивные значения в проект не добавлены.
6. В Яндекс Вебмастере проверить региональность с учётом продвижения по всей России. Если используется Яндекс Бизнес, поддерживать реальные контакты и фактический адрес; часовой пояс Санкт-Петербурга в футере не является почтовым адресом офиса.
7. Проверить опубликованные страницы в валидаторах Schema.org и поисковых систем. Наличие корректного типа Schema.org не означает, что поисковик поддерживает для него расширенный сниппет. Отслеживать индексацию и видимость в Алисе AI через инструменты Вебмастера.
8. При регулярных обновлениях можно подключить IndexNow для Яндекса: создать ключ для своего домена, разместить проверочный файл и отправлять только реально опубликованные изменённые URL. Для текущей локальной версии запросы на переобход не отправляются. Ключи, счётчики аналитики и чужие аккаунты автоматически не подставляются.

HTTPS, региональность, подтверждение владения, индексирование и результаты продвижения проверяются после размещения на основном домене. В этой задаче подготовлены локальные файлы; текущий публичный сайт не заменён.
